# 2026-09-11

- **Font Preload Optimizasyonu:** `app/layout.tsx` üzerinde kullanılmayan font preload stratejisi temizlendi. Sayfa açılışında `The resource ... was preloaded using link preload but not used within a few seconds` konsol uyarısı veren `titilliumWeb` fontunda `preload: false` yapılarak sadece ilk render için zorunlu fontlar (Inter, Syne vb.) preload kapsamına alındı.
- **RSC Nav Link Prefetch Optimizasyonu:** `HeaderNav.tsx` ve `MobileNav.tsx` komponentlerindeki link bileşenlerinde agresif arka plan veri çekimi dizginlendi. Özellikle veri yükü ağır olan rotalarda (`/season`, `/grid`) görülen `net::ERR_ABORTED` iptal hatalarını ve gereksiz bant genişliği tüketimini önlemek için `prefetch={false}` stratejisi ve hover/touch anında yükleme davranışı uygulandı.
- **Cron sync-f1 Hata İzolasyonu & Bildirim Konsolidasyonu:**
  - `app/api/cron/sync-f1/route.ts` içinde per-round döngüsündeki `fetchQualifying`, `fetchSprint` ve `fetchResults` çağrıları yerel `try/catch` bloklarına alındı. Tekil Jolpica ağ veya seans hataları tüm cron akışını kırmayacak şekilde `stats.errors` dizisine yazılarak sonraki tura devam edilmesi sağlandı.
  - Sürücü ve Takımlar şampiyona lider değişimleri için push bildirimleri tek havuzda konsolide edildi; `sendExpoPushNotifications` üzerinden tek seferlik toplu gönderime geçildi ve DB sorguları `Promise.all` ile paralel çalıştırıldı.
- **API f1-season Route & Snapshot Fallback:**
  - `app/api/f1-season/route.ts` içerisinde `applyRateLimit` entegre edilerek IP tespit edilemediğinde bypass yaşanması önlendi (fallback havuzunda 1/5 limit).
  - Jolpica bağımlılığını ve gecikmeyi azaltmak için Supabase snapshot fallback eklendi. İstenen sezon/round/seans `f1_snapshots` tablosunda mevcutsa doğrudan veritabanından dönülüyor; bulunamazsa Jolpica'ya gidiliyor. Jolpica hata/timeout verdiğinde ise stale snapshot'a fallback yapılarak kesintisiz hizmet sağlanıyor (`x-data-source` header eklendi).
- **lib/data/f1.ts Batch Query & OOM Koruması:**
  - `fetchAllRoundResults`: N adet tekil `fetchRoundSnapshot` DB round-trip'i yerine `f1_snapshots` tablosundan tek bir `.in('round', finishedRounds)` batch sorgusu ile tüm sonuçlar tek seferde çekildi; eksik kalanlar için fallback korundu (N+1 problemi çözüldü).
  - `getOnThisDay`: Tüm zamanların `results` kayıtlarının `data` sütununu belleğe çekmek yerine doğrudan PostgreSQL JSON operatörü (`data->MRData->RaceTable->Races->0->>date LIKE %-MM-DD`) ve `.limit(80)` ile filtrelenerek serverless OOM (Out-of-Memory) riski engellendi.
- **Auth & Rate Limiting İyileştirmeleri:**
  - `lib/cronAuth.ts`: Upstash Redis REST API üzerinden dağıtık `SET <key> 1 NX EX <ttl>` lock desteği eklendi; serverless container'lar arası trigger throttle sağlandı, in-memory fallback korundu.
  - `lib/rateLimit.ts`: `applyRateLimit` helper'ı eklendi.
  - `lib/f1/sources/jolpica.ts`: `MAX_RETRIES = 3` seviyesine çekildi ve thundering-herd etkisini engellemek için random jitter eklendi.
  - `lib/f1Ingest.ts`: `round IS NULL` olan sezon seviyesi kayıtlarda TOCTOU penceresini önlemek için insert-first / 23505 unique violation durumunda update akışı optimize edildi.
  - `lib/news/aggregate.ts`: JSDOM tabanlı XML parser singleton haline getirilerek RSS ve HTML parse işlemlerinde aşırı bellek tüketimi önlendi.
